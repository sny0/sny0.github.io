# 四分木と八分木 — 必要な場所だけ細かく分ける

敵が広いマップの一部に集まっているとします。混み合った場所だけを細かく区切れば、広い空き地を同じ細かさで管理せずに、近くの敵を探せます。ここでは、二次元の領域を縦横の中央で分ける**四分木（クアッドツリー）**と、三次元の領域を各軸の中央で分ける**八分木（オクツリー）**を扱います。根が全体の領域を持ち、分割したノードがそれぞれ4個または8個の子領域を持ちます。必要な場所だけで分割を繰り返せます。[Sametによる領域分割と点データの解説](https://www.cs.umd.edu/~hjs/pubs/Samettfcgc88-ocr.pdf)

## 葉に記録するものを決める

| 用途 | ノードや葉が持つもの | 細かく分ける理由 |
| --- | --- | --- |
| 地形やボクセルの占有状態 | 領域の状態。例えば空き、占有、未観測 | 状態の違う場所を区別する。同じ状態が続く領域は1個の葉で表せる |
| 点の位置を検索 | 点の座標やIDの一覧 | 点が集まる場所で、一度に調べる点を減らす |
| 大きさのある物体を検索 | 物体IDと、その物体を包むAABB（軸に平行な境界箱） | 箱が一つの子領域に収まるなら、その子を調べるときだけ検査する |

点を格納する方式では、分割線上の点をどちらの子に入れるかを決めます。例えば `x >= 中央のx` なら右とすれば、同じ点を重複して登録せずに済みます。物体を登録するときは、中心の座標に加えて箱全体がどこまで広がるかを見ます。[Sametによる点と領域の四分木](https://www.cs.umd.edu/~hjs/pubs/Samettfcgc88-ocr.pdf)

## 境界をまたぐ物体は、収まる最も深いノードへ

根から始めて、物体のAABB全体を含む子がちょうど一つなら、その子へ下ります。境界をまたいで一つに収まらない場合は、いまのノードに置きます。分割していない葉や深さの上限でも止めます。この方式では、各物体を1ノードにだけ登録します。箱の端が分割線に触れる場合も含め、登録と検索の境界ルールは揃えます。例えばこの例のように接触も交差に含めるなら、検索枠が境界に触れる子も調べます。[Sametらによる物体を収める領域の選び方](https://www.cs.umd.edu/~hjs/pubs/sigmod13-header.pdf)

範囲検索では、検索枠と交差するノードに入ります。そこで子へ進む前に、そのノードに直接登録された箱も検査します。図では4個の箱のうち、根のAと右上のCの2個を検査すれば結果が得られます。次の擬似コードの結果は、検索枠とAABBが交差した物体です。円やポリゴンとの正確な交差が必要なら、候補に対して形状を使った判定を行います。

```text
範囲検索(ノード, 検索枠, 候補一覧):
    ノードの領域が検索枠と交差しなければ戻る
    ノードに直接登録された各物体について:
        物体のAABBが検索枠と交差するなら候補一覧に追加する
    存在する各子について:
        範囲検索(子, 検索枠, 候補一覧)
```

## 木が深くなり過ぎる場合と、物体が動く場合

- **根の範囲**は、登録する箱全体を含めます。根の外にも物体が移動するなら、根を広げるか、範囲外の物体を別の区画で管理する方針を決めます。
- **分割を止める条件**には、葉の件数だけでなく、最大深さや最小のセル幅を設けます。同じ座標に点が集中すると、細かく分けても同じ子に入り続けます。大きな箱が境界に重なると祖先に集中し、箱の検査は最悪で全件に及びます。
- **移動の更新**では、物体のAABBを更新し、いまの登録先が保持できる範囲を出たら移し替えます。子へ再配置できるようになった物体を下へ移すと、検索時の祖先の検査を減らせます。移動のたびに細かく移し替えるかは、検索と更新の頻度で決めます。

**Loose quadtree / octree** は、各セルの登録・検索に使う境界を広げる方式です。小さな移動なら広げた範囲に留まり、ノード間を移し替えずに済みます。一方、隣接するセルの広げた範囲は重なります。範囲検索では、物体を収めるために使った広い境界で交差を判定する必要があります。元の狭い境界で枝を省くと、セルからはみ出した物体を見落とすためです。[Sametらによる移動物体向けLoose quadtreeの論文](https://www.cs.umd.edu/~hjs/pubs/sigmod13-header.pdf)

## 八分木で三次元の空間を扱う

八分木は上下も分けるので、同じ水平位置にある違う高さの領域を区別できます。例えばOctoMapは三次元の占有地図を八分木で管理し、空きと占有に加えて未観測の空間も区別します。地形や建物のタイルを段階的に読み込む用途では、OGC 3D TilesのImplicit Tilingが四分木と八分木の両方を定義しています。[OctoMapの占有地図の資料](https://octomap.github.io/octomap/doc/index) · [OGC 3D Tiles仕様 §8](https://docs.ogc.org/cs/22-025r4/22-025r4.pdf)

[均等グリッド](/algorithms/uniform-grid-and-spatial-hash.html)は全体を同じ幅で区切るので、セルの位置を座標から直接計算できます。四分木・八分木は場所によって分割の深さを変えられます。[BVH](/algorithms/bounding-volume-hierarchies.html)の代表的な作り方では、物体をグループに分けて各グループを包む境界を作ります。子の境界同士は重なることがあります。どの方式も、検索時に領域や箱を調べる回数と、更新時に登録先を移し替える手間が分布や動き方で変わります。キーの大小関係で枝を選ぶ木は[二分探索木](/algorithms/search-trees.html)で扱います。
