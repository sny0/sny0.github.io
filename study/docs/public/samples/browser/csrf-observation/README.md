# CSRFの判定と、実際のフォーム送信

[公開サンプル](https://sny0.com/study/samples/browser/csrf-observation/index.html)は、Cookieを送る条件を満たしたと仮定して、送信元や検査の違いを比べるシミュレーションです。実際のHTTP要求を観察するローカル版も付属します。[実践手順](https://sny0.com/study/practice/browser/csrf-observation.html)

## 公開モデル

追加検査を選び、「アプリ側のフォームから送る」と「別オリジンのフォームから送る」を比べます。結果には、要求のOrigin、Cookieとトークンの有無、選んだ検査、教材用カウンターの変化が出ます。手元で試す場合は、`index.html`、`styles.css`、`main.js` を同じディレクトリに置き、静的HTTPサーバーで配信します。

## ローカル版

`server.py` を保存し、Python 3.10以降で起動します。一つのプロセスがループバックの4190番と4191番を使います。

```powershell
python server.py
```

1. `http://127.0.0.1:4190/csrf-lab/` を開き、「教材セッションを開始」を押します。各カウンターは0から始まります。
2. 「別オリジンのページへ」から `http://127.0.0.1:4191/csrf-other/` へ進み、「追加検査なしの経路へ送信」を押します。アプリが受け取ったOriginには4191番が含まれ、Cookieは「あり」、カウンターは1になります。
3. 結果ページから別オリジン側に戻り、Origin照合とトークン照合を試します。Cookieが届いても、Originの不一致、またはトークンの欠落によって拒否されます。
4. アプリ側に戻って「トークンを照合する経路へ送信」を押します。アプリが作ったフォームのトークンが届き、照合に成功するとトークン用カウンターが増えます。
5. アプリ側で「ログアウト」を押し、端末でCtrl+Cを押して終了します。

ポートが異なるため別オリジンですが、ホストとスキームを共有する同一サイトです。教材用のCookieはhost-onlyで `HttpOnly`、`SameSite=Strict`、`Path=/csrf-lab/`、`Max-Age=120` を指定します。アプリ宛てのフォームがPOSTを送ると、宛先の条件を満たすCookieが付きます。120秒を過ぎたらアプリ側でセッションを開始し直せます。

サーバーは教材で使う二つの送信元だけを受け付けた上で、各経路の検査を適用します。アプリのフォームのうちトークン照合用だけに、セッションと結び付けたトークンを入れます。観察画面とサーバーのログにはIDやトークンの値を表示せず、カウンターとセッションはプロセスのメモリに置きます。
