元のデータはどうなる？

16バイトの同じデータでコピーとtransferを比較します。workerの起動完了を待ち、一件ずつ要求と返信を見比べる実験です。

1. Workerを起動する

HTTPまたはHTTPSで、このページとworker.jsを同じoriginから配信してください。

カウンター：0

状態：停止

要求はありません。

起動と各要求には8秒のsoft timeoutを設けます。厳密な実時間の終了保証ではありません。カウンターは待機中も操作できます。

2. readyになったら一つ試す

A / COPY

コピーして送る

転送リストなしのpostMessage。workerで先頭を255へ変えても、送信元の先頭は0のままです。

B / TRANSFER

所有権を移して送る

bufferをpayloadと転送リストへ入れます。送信直後は元のbyteLengthが0。返信時もtransferします。

C / DELAYED REPLY

3秒の遅延応答

workerのtimerへ3000msを指定します。重いCPU処理ではありません。待つ間にカウンターや停止を試せます。

D / DATA CLONE ERROR

関数は送れる？

関数を含む値を送ろうとして、main側のpostMessageが同期的に投げるDataCloneErrorを確認します。

payloadは16バイトの0〜15。workerは変更前の長さ・先頭・合計120を調べ、先頭だけ255へ変更します。数値はこのfixtureの検査条件です。

    この実験の範囲

    HTTPまたはHTTPSで、このページとworker.jsを同じoriginから配信してください。手元でもローカルHTTPサーバーから開きます。Workerの起動時にスクリプトを取得し、実験中は固定のメッセージをやり取りします。

    mainとworkerは、それぞれのイベントループでメッセージを処理します。workerの値をmainが直接読むのではなく、返信された値を表示します。copyとtransferの速度やGPU・CPU性能を比較するベンチマークではありません。

    停止はmainからWorker.terminate()を呼び、古いworkerからの表示を無効にします。停止ボタンのクリック処理自体は、mainで実行中のJavaScriptへ割り込む命令ではありません。
