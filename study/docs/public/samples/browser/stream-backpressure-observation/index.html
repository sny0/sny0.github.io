1. 接続して、完了または中断を待つ

状態：待機中

完了はpipeToのPromiseがfulfilledになった時点です。中断要求後も、Promiseがsettledになるまで再実行しません。

カウンター：0

外部データの取得はありません。timerは正確な実行時刻の保証ではなく、背景タブや負荷で遅延し得ます。

処理とcallbackのログ 最新60件

mainが記録したperformance.now()です。source.cancel、sink.abort、pipeToの拒否の順を固定保証するものではありません。

    中断の後片付けと観測範囲

    pipeToと進行中writeの待機timerへ同じsignalを使います。中断時はtimerをclearし、その待機Promiseとwriteをsignal.reasonでrejectして片付けます。このwriteを通常消費完了には数えません。writeの部分的な作用が自動rollbackされる意味ではありません。

    中断要求後も、既に読み取られたchunkのwriteが始まる場合があります。その待機も同じsignalで片付けます。実際のsource.cancelとsink.abortのcallbackを記録しますが、状態によって両方が必ず呼ばれるとは限りません。sourceが既にclosedの場合、両callbackが0回でも進行中writeのrejectがpipeToへ伝わる経路があります。pipeToの終端を回収してからlock状態を表示し、再実行できます。

    固定8chunkのメモリ内モデルです。ネットワークfetch、ファイル保存、CPU並列処理、メモリ使用量の上限保証を実演するコードではありません。外部ライブラリ、storage、analytics、busy loopは使いません。
