# 第12章 レンダリングパイプラインとシェーダ ── 頂点からピクセルまで

## 学ぶ理由

「画面にゲームが表示される」の中身がこの章だ。三角形の頂点データが
どんな段階を経て液晶の1ピクセルの色になるのか ── この変換の連鎖を
知らないままマテリアルを組むのは、文法を知らずに外国語を話すのに等しい。
RenderDocで1フレームを追える(最終目標)とは、**このパイプラインの
各段階を画面上で識別できる**ということである。

## 到達目標

- グラフィックスパイプライン全段を順番に説明できる
- HLSL/GLSLで頂点シェーダ・ピクセルシェーダを書ける
- 深度バッファ・アルファブレンド・カリングの原理と設定を説明できる
- ライティングの基礎(ランバート、スペキュラ、法線マップ、PBRの概念)を実装できる
- フォワード/ディファードレンダリングの違いと選択理由を説明できる
- RenderDocで各パイプライン段階の入出力を検査できる

## 前提知識

第10章(ベクトル・行列・MVP変換)、第11章(GPU)。

## 学ぶ内容

1. **パイプライン全景(暗唱レベルにする)**
   ```
   頂点バッファ/インデックスバッファ (VRAM)
     → [入力アセンブラ IA]     頂点を読み集める
     → [頂点シェーダ VS]       MVP変換・スキニング (プログラマブル)
     → (テッセレーション/ジオメトリ/メッシュシェーダ)  (任意)
     → [クリッピング/透視除算/ビューポート変換]  NDC→スクリーン
     → [ラスタライザ]          三角形→ピクセル候補(固定機能)
        属性の透視補正付き補間(UV・法線・色)
     → [ピクセルシェーダ PS]   色を計算 (プログラマブル)
     → [出力マージャ OM]       深度テスト・ステンシル・ブレンド
     → フレームバッファ (VRAM) → Present → 画面
   ```
2. **座標変換の実装(第10章の回収)**
   - モデル→ワールド→ビュー→クリップ→NDC→スクリーン
   - w除算と透視補正補間、深度値の非線形性(Zファイティングの原因)
3. **シェーダプログラミング(HLSL中心、GLSL併記)**
   - セマンティクス、定数バッファ(cbuffer)、テクスチャとサンプラ
   - 頂点シェーダ: MVP乗算、法線変換、スキニング(ボーン行列)
   - ピクセルシェーダ: テクスチャサンプリング、ライティング
   - シェーダのコンパイル経路: HLSL→DXC→**DXIL**(中間言語)→
     ドライバ→GPU ISA(第11章の回収)。GLSL→SPIR-Vも同じ構図
4. **ライティング**
   - ランバート拡散(=内積!)、Blinn-Phongスペキュラ
   - 法線マップ(接空間)、環境光
   - **PBRの概念**(エネルギー保存・金属/粗さワークフロー、
     Cook-Torranceの式は「読める」程度でよい)
   - シャドウマップ(深度を光源から描く、という発想の転換)
5. **出力マージャの攻防**
   - 深度テスト(Zバッファ法)、early-Z、Zプリパス
   - アルファブレンドと**描画順問題**(半透明ソート、加算合成)
   - バックフェースカリング
6. **テクスチャの実務**
   - ミップマップ(なぜ必要か: エイリアシングとキャッシュ)、
     フィルタリング(バイリニア/トライリニア/異方性)
   - sRGBとリニアワークフロー(第1章の回収。「暗くなる/白飛びする」の正体)
   - 圧縮フォーマット(BC1-7)
7. **レンダリング戦略(エンジンの設計判断)**
   - フォワード / ディファード(Gバッファ)/ フォワード+
   - ポストプロセス(トーンマップ、ブルーム、TAA)の概観
   - 現代トピックの地図: メッシュシェーダ、GPU駆動描画、
     Nanite/Lumen(第17章)、レイトレ(発展編)
8. **RenderDoc入門(以後の常用ツール)**
   - フレームキャプチャ→イベントブラウザ→各ステージの入出力表示
   - テクスチャビューア、メッシュビューア、ピクセル履歴、シェーダデバッグ

## 重要概念

- **パイプラインは流れ作業** ── 各段の入出力を言えることが「理解」
- **プログラマブル(VS/PS)と固定機能(ラスタ/OM)の分業**
- **深度バッファ** ── 3D描画を成立させている単純で偉大な仕組み
- **補間** ── 頂点で計算した値がピクセルに届く仕組み
- **リニアワークフロー** ── 色計算の正しさの土台

## ゲーム開発との関係

| 現場の事象 | この章の知識 |
|---|---|
| マテリアル/シェーダグラフの中身 | 生成されるのはこの章のシェーダ |
| 半透明の前後関係バグ | ブレンドと描画順・深度書き込み |
| Zファイティング | 深度精度・ニア/ファー設定 |
| 遠景がチラつく | ミップマップ・エイリアシング |
| 「ピクセル負荷が高い」 | PS・解像度・オーバードロー |
| ライトを増やすと重い→ディファード | レンダリング戦略 |
| 色味がsRGB設定で変わる | リニアワークフロー |

## 演習

**この章から「自作ミニレンダラ」が始まる。教材はLearnOpenGL
(またはDirectX11)。APIの詳細は第13章で深めるので、ここでは
「パイプラインを動かして理解する」ことに集中する。**

1. **ソフトウェアラスタライザ(強く推奨)**: GPUを使わず、CPUだけで
   三角形を塗るプログラムを書け(エッジ関数、重心座標補間、Zバッファ、
   テクスチャ、簡単なシェーディング)。「ラスタライザが何をしているか」が
   永久に自分のものになる。(教材: tinyrenderer)
2. LearnOpenGL(またはDX11版チュートリアル)で:三角形→テクスチャ→
   MVP変換で回る立方体→ランバート+スペキュラ→法線マップ→
   シャドウマップ まで進めよ。
3. 各演習をRenderDocでキャプチャし、(a)頂点入力 (b)VS出力
   (c)ラスタ後のPS入力 (d)OM後の出力 を確認する習慣をつけよ。
4. 深度テストを切る/ブレンドを加算にする/カリングを反転する ──
   それぞれ画面がどう壊れるかを観察し、理由を説明せよ。
5. わざとZファイティングを起こし、ニアクリップを遠ざけて改善せよ。
6. Shadertoyでピクセルシェーダのみの作品(レイマーチング入門)を1つ書け
   (PSの理解が深まる遊び場として)。

## 理解度チェック

1. パイプラインの各段階を順に挙げ、プログラマブル/固定機能を区別せよ。
2. 頂点シェーダとピクセルシェーダの実行回数はそれぞれ何に比例するか。
3. ラスタライザは何を入力し何を出力するか。「補間」とは何か。
4. Zバッファ法を説明せよ。半透明がZバッファだけで解決できないのはなぜか。
5. ミップマップが画質と性能の両方に効く理由は?
6. ランバート拡散の式を書け。内積の幾何的意味(第10章)との関係は?
7. フォワードとディファードの違い、それぞれの得意・不得意は?
8. sRGBテクスチャをリニア変換せずにライティングすると何が起きるか?

## この章がゲームのどこで使われているか

```
「画面にゲームが表示される」の正体(毎フレーム)
────────────────────────────────────────────
エンジンが発行した数百〜数千のドローコールそれぞれについて:
 頂点バッファ→[IA]→[VS: MVP変換]→[ラスタ]→[PS: テクスチャ+ライト]
 →[OM: 深度/ブレンド]→フレームバッファ
────────────────────────────────────────────
 不透明パス → スカイ → 半透明パス → ポストプロセス → UI
 (エンジンはこの章の知識で描画パスを設計している)
RenderDocの1キャプチャ = この図を実物で眺める行為
UnityのShaderGraph/UEのマテリアルエディタ = この章のシェーダ生成UI
```
