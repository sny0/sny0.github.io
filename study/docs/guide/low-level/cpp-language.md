# 第9章 C++ ── ゲーム業界の母語を「中身から」理解する

## 学ぶ理由

UE5はC++で書かれ、Unityのコアも C++、主要な自社エンジンもC++である。
だが「C++が書ける」と「C++で何が起きているか分かる」は別物だ。
この章では、型とオブジェクト寿命の規則を押さえたうえで、代表的な実装を
C風の擬似コードやアセンブリで観察する。これは説明モデルであり、C++の全機能を
Cへの単純な置換で定義できるという意味ではない。ABIや最適化による違いも確かめる。

## 到達目標

- クラス・仮想関数のメモリレイアウト(vtable)を図示できる
- RAIIと所有権(unique_ptr/shared_ptr)を使い分け、循環参照を指摘できる
- ムーブセマンティクスを説明でき、不要コピーを見抜ける
- テンプレートの実体化とコンパイル時間・コード膨張の関係を説明できる
- 例外・RTTIをゲームが無効化しがちな理由を説明できる
- 「ゲームスタジオ方言のC++」(UEコーディング規約等)を読める

## 前提知識

第4〜7章(アセンブリ・C・ポインタ・リンカ)。C++の文法経験(2年目想定)。

## 学ぶ内容

1. **クラスとは何か(言語の規則と典型的な実装)**
   - 非staticメンバ関数を、暗黙のthis引数を渡す関数として観察する(典型的なABIの説明モデル)
   - コンストラクタ/デストラクタ = 初期化・後始末関数の自動呼び出し
   - アクセス制御はコンパイル時のみの概念(実行時コストゼロ)
2. **仮想関数の完全理解**
   - vtable/vptrは典型的な実装。単純な継承ではvptrを1本持つモデルで説明できるが、
     多重継承等では複数になる場合があり、C++規格が本数や表の配置を規定するわけではない
   - 仮想呼出しの例: vptrロード→関数アドレスのロード→間接call。
     キャッシュ・分岐予測・インライン化の可否が効く。脱仮想化で直接呼出しになる場合もある
   - 継承・多重継承・仮想継承のレイアウト(多重以降は概念だけで可)
   - dynamic_cast/RTTIの仕組みとコスト
   - **ホットループで仮想関数を嫌う理由が、ここまでの章の総決算として分かる**
3. **RAIIと所有権(モダンC++の心臓)**
   - デストラクタによる確定的リソース解放 ── GC言語との最大の違い
   - unique_ptr(単独所有・参照カウント不要。サイズ等はdeleter/実装による)/shared_ptr(参照カウント・
     制御ブロック・アトミック増減のコスト)/weak_ptr(循環切り)
   - 生ポインタ=「所有しない参照」という現代規約
   - ゲームでの現実: shared_ptr多用は嫌われる。ハンドル/ID参照が主流
     (UEのTObjectPtr、EntityIDなど ← 第15章へ伏線)
4. **値セマンティクスとムーブ**
   - コピーコンストラクタ/代入、暗黙生成(rule of 0/3/5)
   - 右辺値参照とムーブ = 「中身の引っ越し」(vector成長時の差を計測)
   - std::move はキャストにすぎない
   - 戻り値のRVO/NRVO(コピーは意外と起きていない)
5. **テンプレートとコンパイル時プログラミング**
   - テンプレートは型や値等をパラメータとする仕組み。実体化はコンパイル時間や
     コード量を増やす場合があるが、不要なコードの除去や同一コードの統合も行われる
   - 特殊化、SFINAE(概念のみ)→ C++20 concepts
   - constexpr(条件を満たせば定数式で評価可能。関数は実行時にも呼べる)、auto、CTAD
   - なぜヘッダに書くのか(第7章ODRの回収)
6. **STLの中身**
   - vector(連続・成長戦略・再確保時のイテレータ無効化)
   - unordered_map(バケット・ハッシュ・キャッシュに不利)
   - string(SSO: 短い文字列をstringオブジェクト内に保持する典型的な最適化。
     string自体がヒープ上なら内部文字もそこにある。採用や容量は実装による)
   - アロケータ差し替え、ゲームがEASTL/自作コンテナを持つ理由
7. **例外とエラー処理**
   - 例外の仕組み(テーブル方式、正常系ほぼゼロコスト・throwは超高価)
   - ゲームが例外を切る文化(-fno-exceptions / UEも既定オフ)と
     代替(戻り値、optional、expected、assert)
8. **ゲームC++方言**
   - UEコーディング規約(前置詞F/U/A/T、GC対象UObjectの世界)
   - 禁止されがちな機能(例外・RTTI・iostream・多重継承)とその理由

## 重要概念

- **ゼロオーバーヘッド原則** ── 使わない機能にコストを払わず、使う機能は手書き実装と同等の効率を目指す設計原則。
  全機能が無コストという意味ではない。例外・RTTI・shared_ptr等の必要なコストも具体的に調べる
- **vtable** ── 動的ポリモーフィズムの実装コスト
- **RAII** ── 資源の管理を所有オブジェクトの寿命に結び付ける。自動変数ではスコープ退出時の破棄を利用する
- **所有権の型表現** ── unique/shared/生ポインタ/ハンドル
- **テンプレート=コード生成** ── 柔軟さとビルド時間のトレードオフ

## ゲーム開発との関係

| 現場の事象 | この章の知識 |
|---|---|
| UE5のソースがそのままこの章の実物 | 全部 |
| Update()を仮想関数で回すと遅い問題 | vtable+キャッシュ → ECSへ(15章) |
| ScopedLock/ScopedTimerパターン | RAII |
| vector.push_backでポインタが無効に | 再確保・イテレータ無効化 |
| ビルドが遅い/バイナリが巨大 | テンプレート実体化・ヘッダ依存 |
| 例外禁止・RTTI禁止の規約 | コストの理解 |
| shared_ptr循環でリーク | 参照カウントの限界 |

## 演習

1. 仮想関数を持つクラスの `sizeof` を継承階層で観察し、VSのメモリ
   ウィンドウ+逆アセンブリでvptrとvtable経由callを実際に確認せよ。
2. 同じ処理を (a)仮想関数呼び出しの配列 (b)型別に分けた配列+非仮想
   で100万回回し、速度差を計測せよ(第15章ECSの動機を先取り)。
3. RAIIでファイルハンドル/ミューテックス/GPUリソース(ダミー)の
   ラッパを書け。例外や早期returnでも解放されることを確認せよ。
4. コピー/ムーブ/RVOの発生をログするクラスを作り、vector成長・関数戻り値
   などでいつ何が呼ばれるか観察せよ。
5. shared_ptrの循環参照リークを作り、weak_ptrで直せ。
6. `std::sort` と関数ポインタ渡しqsortの逆アセンブリを比較し、
   テンプレート(インライン化)が速い理由を説明せよ。
7. 固定容量の `static_vector<T, N>`(ヒープ非使用)を自作せよ
   (ゲームで多用される。placement newを学べる)。

## この章がゲームのどこで使われているか

```
UE5 = この章の巨大な実物展示
┌──────────────────────────────────────────────┐
│ AActor::Tick()          ← 仮想関数(vtable)      │
│ TArray/TMap             ← 自作テンプレートコンテナ │
│ TUniquePtr/TSharedPtr   ← 所有権の型表現          │
│ FScopeLock              ← RAII                   │
│ UPROPERTY()+GC          ← 独自GC(C++の上に構築)  │
│ MODULE_API              ← DLLエクスポート(第7章)  │
└──────────────────────────────────────────────┘
ゲームループ内: 毎フレーム数万回の仮想呼び出し・数千のRAIIスコープ・
テンプレート展開済みの機械語が走る。AI生成コードのレビュー
(「このshared_ptr渡しは重い」等)もこの章の目で行う。
```
