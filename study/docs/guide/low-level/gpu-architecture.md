# 第11章 GPUアーキテクチャ

## このページで案内すること

GPUの実行単位、メモリ階層、並列処理の制約を学び、プロファイラで観察するための**学習計画・概要**です。CPUとの比較から入り、対象GPUの資料と測定結果を対応させます。

## 関連する辞典本文・実践

- [GPUとは何か](/hardware/gpu/what-is-gpu.html)と[GPUアーキテクチャ](/hardware/gpu/architecture.html)で、構成と役割を調べられます。
- [Warp / Waveの実行モデル](/graphics/compute/execution-model.html)では、並列実行と分岐の扱いを掘り下げます。

## 学ぶ理由

シェーダを書き、RenderDocでフレームを追い、描画負荷を最適化するには、
「GPUというハードウェアがCPUと何が違うのか」を知らなければならない。
「ドローコールが多いと重い」「分岐がシェーダで嫌われる」「帯域が足りない」
── これらの決まり文句は、GPUの実行モデル(SIMT・ワープ・メモリ帯域)を
知って初めて**理由ごと**理解できる。

## 到達目標

- CPUとGPUの設計思想の違い(レイテンシ指向 vs スループット指向)を説明できる
- SIMT実行モデル(ワープ/ウェーブ、アクティブマスク、分岐ダイバージェンス、同期)を説明できる
- GPUメモリ階層(レジスタ・共有メモリ・VRAM・帯域)を説明できる
- オキュパンシとレイテンシ隠蔽の関係を説明できる
- 「CPUバウンド/GPUバウンド」「帯域バウンド/ALUバウンド」を区別できる
- CPU→GPUの接続(PCIe・ドライバ・コマンドバッファ・DMA)を説明できる

## 前提知識

第2章(CPU)、第3章(メモリ・キャッシュ)、第8章(OS・ドライバ・DMA)。

## 学ぶ内容

1. **設計思想: レイテンシ指向 vs スループット指向**
   - CPU: 少数の賢いコア。1本の処理を最速で(分岐予測・OoO・巨大キャッシュ)
   - GPU: 数千の単純なALU。100万ピクセルを「まとめて」最速で
   - 「1ピクセルの処理は遅くていい。全部終わるのが速ければいい」
2. **SIMT実行モデル(最重要)**
   - スレッドを束ね、アクティブなレーンへ命令を発行する。NVIDIAのワープは32スレッド。
     AMDのウェーブ幅はアーキテクチャ/実行モードによる(32/64等)。暗黙の同期を保証する仕組みではない
   - **分岐ダイバージェンス**: ワープ内で分岐が割れると両方のパスを
     実行してマスクする → シェーダのif文が重くなる条件の正体
   - SIMDとの関係: 命令を複数データへ適用する点は似るが、SIMTはthreadごとの
     制御フローを表現する。NVIDIA Volta以降にはIndependent Thread Schedulingがあり、
     ワープ内が常にロックステップで進む前提の共有メモリ処理は避け、必要な明示同期を使う
3. **GPUの構造**
   - SM/CU(実行ユニットのクラスタ)、レジスタファイル、共有メモリ(LDS)
   - 固定機能ハードウェア: ラスタライザ、テクスチャユニット(フィルタリング)、
     ROP(ブレンド・深度)、(近年)RTコア・テンサーコア
   - 「シェーダコアだけがGPUではない」── 固定機能が massive に働いている
4. **メモリ階層と帯域**
   - レジスタ、明示的に使う共有メモリ/LDS、L1/L2キャッシュ、VRAM(GDDR/HBM)。
     全てのアクセスがこの順に通るという一本道ではない
   - **帯域(数百GB/s)こそGPUの生命線**。テクスチャ圧縮(BC/ASTC)や
     ミップマップが「品質のため」だけでなく「帯域のため」であること
   - 統合メモリ(コンソール・スマホ・Apple)とディスクリートGPUの違い
     → コンソール最適化の文脈
5. **レイテンシ隠蔽とオキュパンシ**
   - メモリ待ちの間、別のワープに即切り替えて隠す(CPUのOoOに相当する解決策)
   - オキュパンシ: 例えばCUDAではSM当たりのアクティブワープ数の最大数に対する割合。
     レジスタ/共有メモリ等の使用量に制約される。高いほど必ず速いという指標ではない
     → 「シェーダのレジスタ数を減らすと速くなる」ことがある理由
6. **CPUからGPUへの道(第13章への橋)**
   - ゲーム → API → ユーザーモードドライバ(コマンド生成)→
     カーネルモードドライバ → リングバッファ → GPUフロントエンド
   - DMA転送、PCIeの帯域、**CPUとGPUは非同期に走る別のコンピュータ**
   - GPUにも「命令セット」がある(ISAはベンダ毎。シェーダは中間言語
     DXIL/SPIR-Vからドライバがコンパイル ← 第12章へ)
7. **性能の切り分け入門(第18章の予習)**
   - フレーム時間の二大区分: CPUバウンド / GPUバウンド(判定方法)
   - GPU内の区分: 頂点/ピクセル/帯域/ALU/固定機能のどこが詰まるか

## 重要概念

- **スループット指向** ── GPU設計のすべてを説明する一語
- **ワープ/ウェーブとダイバージェンス** ── シェーダ最適化の基礎文法
- **帯域は最も貴重な資源** ── 圧縮・ミップ・フォーマット選択の理由
- **レイテンシ隠蔽** ── 「待つ代わりに切り替える」
- **CPUとGPUは非同期な別コンピュータ** ── 同期(フェンス)が必要な理由(第13章)

## ゲーム開発との関係

| 現場の事象 | この章の知識 |
|---|---|
| 「シェーダで分岐するな」の真偽 | ダイバージェンス(揃った分岐は安い) |
| テクスチャ圧縮・ミップマップ必須 | 帯域・テクスチャキャッシュ |
| 解像度を下げたら速くなった | ピクセル負荷・帯域バウンド |
| ドローコール削減・インスタンシング | CPU→GPUコマンドのコスト(第13章) |
| コンソールとPCで最適化が違う | 統合メモリ/ディスクリート |
| 「GPUバウンドだからCPU最適化は無意味」 | 非同期実行・ボトルネック思考 |

## 演習

1. 自分のGPUのスペック表(コア数・クロック・帯域)から理論FLOPSと
   帯域を計算し、CPUと比較せよ。演算の種類・精度・FMAの数え方を揃え、
   理論ピーク比をそのままアプリの速度比としない。
2. タスクマネージャ/GPU-Zで、ゲーム実行中のGPU使用率・VRAM・
   各エンジン(3D/Copy)の動きを観察せよ。
3. (第12章のシェーダ習得後に戻って)同じ処理を「ワープ内で揃う分岐」と
   「ピクセル毎にバラバラの分岐」で書き、フレーム時間を比較せよ。
4. 非圧縮テクスチャとBC圧縮テクスチャで同じシーンを描画し、
   フレーム時間とVRAM使用量を比較せよ(第13章の環境で)。
5. 「1920x1080、60fps、1ピクセル平均4回のRGBA8参照」を、1参照が4byteの
   論理読取りと仮定して概算せよ。1920×1080×60×4×4 = 1,990,656,000byte/s、
   約1.99GB/s(十進単位)となる。これは仮定した論理読取量/秒であり、実DRAM帯域の
   上限・下限ではない。キャッシュ再利用、フィルタリング、アクセス粒度、圧縮、
   overdraw等で実際の転送量は変わる。GPUの測定値と量の定義を揃えて比較する。

## この章がゲームのどこで使われているか

```
フレーム後半戦の主役
┌─CPU──────────────┐     ┌─GPU(別のコンピュータ)─────────────┐
│ ゲーム更新        │     │ 前フレームの描画を実行中(非同期!)     │
│ 描画コマンド生成  ─┼─DMA→│ コマンド読取→頂点→ラスタ→ピクセル    │
│ Present呼び出し   │     │ →ROP→フレームバッファ(VRAM)         │
└──────────────────┘     └───────────────────────────────────┘
 数千ALUが100万ピクセルを並列処理 / 帯域数百GB/sをやりくり
 ワープ単位でシェーダ実行(第12章) / 完了をフェンスでCPUに通知(第13章)
```
