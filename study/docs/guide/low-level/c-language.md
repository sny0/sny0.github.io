# 第5章 C言語 ── メモリと機械語への接続

## 学ぶ理由

Cのポインタ・構造体・動的メモリ管理は、OSやライブラリ、ゲームエンジンの
低レイヤを読む基礎になる。C++とは多くの構文を共有するが、型・初期化・
オブジェクト寿命等の規則は異なり、全てのCプログラムがC++として通るわけではない。
Cの処理を第4章のアセンブリと対応させて学ぶ。ただし言語の意味と機械語は
一対一ではなく、最適化で処理が除去・統合・並べ替えられることがある。

## 到達目標

- C99/C11の主要機能を使い、数百行のプログラムを設計・実装できる
- 代表的な構文がどう命令列になるかを観察し、最適化による違いを説明できる
- 構造体のメモリレイアウトを図示できる
- 未定義動作(UB)という概念を説明でき、代表例を5つ挙げられる
- stb_image程度のCライブラリのソースを読める

## 前提知識

第1章(ビット)、第3章(メモリ)、第4章(アセンブリ・スタック)。

## 学ぶ内容

1. **言語の基本(2年目なら高速で)**
   - 型(整数の暗黙変換規則に注意)、制御構文、関数
   - オブジェクトの記憶域期間: 自動/静的/スレッド(C11)/割り当て。
     スタックやヒープは典型的な実装上の置き場所であり、この分類と同義ではない。
     自動記憶域の変数がレジスタに置かれたり、最適化で実体を持たなかったりする場合もある
   - スコープと寿命は別概念であることを明確に
2. **配列と文字列**
   - 配列は同じ要素型のオブジェクトが連続する型。ポインタとは異なり、要素数も型に関わる
   - 配列は式の中でポインタに退化(decay)する ── `sizeof`との罠
   - C文字列 = '\0'終端のchar配列。strcpy系の危険性、バッファサイズ管理
3. **構造体と共用体**
   - メモリレイアウト(第3章のパディング再訪)
   - 構造体の値渡し/ポインタ渡しのコスト差(アセンブリで確認)
   - union: 同じメモリの複数解釈(型パンニングはmemcpyが安全)
   - ビットフィールド(ハードウェアレジスタ・パケット表現)
4. **関数ポインタ**
   - シグネチャの読み方 `int (*cmp)(const void*, const void*)`
   - コールバック設計(qsort)、関数テーブル
   - **これがC++の仮想関数・デリゲートの原始形**
5. **プリプロセッサ**
   - #include の実体(テキスト展開)、ヘッダガード
   - #define のマクロと罠(副作用・多重評価)、#ifdef によるプラットフォーム分岐
   - **翻訳単位**という概念(第7章コンパイラへの伏線)
6. **標準ライブラリの最小セット**
   - stdio: FILEはバッファ等を持つストリームを表す。OS側のfd/handleとの対応は
     処理系に依存し、C規格がファイルディスクリプタを要求するわけではない(第8章へ)
   - string.h / stdlib.h / math.h
7. **未定義動作(UB)入門**
   - 配列範囲外、符号付きオーバーフロー、NULL参照外し、初期化忘れ、
     解放後使用
   - 「たまたま動く」が最悪。UBはコンパイラ最適化の前提条件である、
     という視点(第7章で回収)
8. **C的設計スタイル**
   - データ(struct)と操作(関数)の分離
   - ハンドル+関数群のAPI設計(`Texture* tex = tex_load(...)`)
     ── SDLやWin32 APIの様式

## 重要概念

- **型の規則とオブジェクトの寿命に従ってメモリを扱う** ── 生バイトの解釈にも制約がある
- **配列とポインタの関係**(同じではない。だが混ざる)
- **値渡しがすべて**(ポインタ渡しも「アドレスの値渡し」)
- **翻訳単位と宣言/定義の区別** ── リンカ理解(第7章)の前提
- **UB** ── メモリ安全性等を損なう重要な原因。仕様を満たすコードにも論理・設計上のバグはあり得る

## ゲーム開発との関係

| 現場の事象 | この章の知識 |
|---|---|
| Win32 API / SDL / stbなどC APIの利用 | Cの API様式・ハンドル設計 |
| バイナリアセットの読み書き | struct+fread/エンディアン |
| 「.hに実装書いたらリンクエラー」 | 翻訳単位・宣言と定義 |
| プラットフォーム分岐 `#if PLATFORM_SWITCH` | プリプロセッサ |
| メモリ破壊系の不可解バグ | UBの知識 |
| コールバック/イベント設計 | 関数ポインタ |

## 演習

1. **バイナリファイル演習**: BMPファイルをfreadで構造体に読み込み、
   ネガポジ反転して書き出すプログラムを書け(ライブラリ禁止)。
2. **動的配列**: `realloc`で伸びるint用動的配列(push/get/free)を実装し、
   `std::vector`の原型を体感せよ。
3. **関数ポインタ**: qsortに自作比較関数を渡して構造体配列をソートせよ。
   さらに「状態(state)を持つ更新関数テーブル」で敵AIのステートマシンを書け。
4. **ミニ演習の王道**: テキストのライフゲーム、逆ポーランド電卓、
   簡易ハッシュテーブル(固定長・チェイン法)を書け。
5. 各演習でVSの逆アセンブリを開き、構造体アクセスと関数ポインタcallが
   どんな命令になるか確認せよ(第4章との接続)。

## 理解度チェック

1. `int a[10]` と `int* p` の違いを、sizeof・代入・メモリの観点で述べよ。
2. ローカル変数・static変数・malloc領域はそれぞれメモリのどこにあり、
   寿命はいつまでか。
3. `struct {char c; int i; short s;}` のsizeofを予想し、根拠を述べよ。
4. 関数ポインタはアセンブリレベルでは何か? 仮想関数との関係を予想せよ。
5. UBを3つ挙げ、それぞれ実ゲームでどんな事故になるか例を述べよ。
6. ヘッダに関数の実装を書くと何が起きるか(翻訳単位の言葉で)。

## この章がゲームのどこで使われているか

```
ゲーム開発の足元は今もC的世界
┌──────────────────────────────────────────┐
│ Win32 / XInput / D3D12のCOM             │← C様式のAPI(第8,13,14章)
│ SDL / stb / cJSON等の定番ライブラリ       │← Cで書かれている
│ アセットのバイナリフォーマット            │← struct+バイト列(第1,5章)
│ UE5内部の低層(FMemory等)・Unityネイティブ │← C的コードの塊
│ シェーダ言語HLSL/GLSL                    │← C系文法(第12章)
└──────────────────────────────────────────┘
パッド入力を受け取るXInputGetState()もCの関数。
「Cが読める」=ゲームスタックのどの層のソースも読み始められる。
```
