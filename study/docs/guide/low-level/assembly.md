# 第4章 アセンブリ ── コンパイラの出力を読む力

## 学ぶ理由

アセンブリを**書く**仕事はほぼないが、**読む**場面は確実にある:
リリースビルドだけで起きるクラッシュの解析、最適化が効いているかの確認、
AI生成コードが本当に速いかの検証、チートやバグの原因究明。
「Visual Studioでアセンブリまで追える」という最終目標の中核であり、
次章のC言語(ポインタ・関数呼び出し)を一発で理解するための下地でもある。

## 到達目標

- x64の主要レジスタ(RAX〜R15, RSP, RBP, RIP, XMM)の役割を言える
- mov/lea/add/cmp/jcc/call/ret/push/pop を読める
- 関数呼び出しの仕組み(スタックフレーム、呼出規約)を説明できる
- VSの逆アセンブリウィンドウでC++コードと機械語の対応を追える
- Compiler Explorerで最適化の有無による出力差を読める

## 前提知識

第2章(CPU・命令・レジスタの概念)、第3章(メモリ)。

## 学ぶ内容

1. **x64レジスタセット**
   - 汎用: RAX(戻り値), RCX/RDX/R8/R9(Win引数), RSP(スタックポインタ),
     RBP, RSI, RDI, R10〜R15
   - RIP(命令ポインタ)、RFLAGS(比較結果)
   - XMM0〜15(float/SIMD)── floatの引数・戻り値はXMM
   - 32bit名(EAX)や8bit名(AL)は同じレジスタの部分ビュー
2. **主要命令(これだけで9割読める)**
   - `mov dst, src`(転送)、`lea`(アドレス計算/乗加算の裏技)
   - `add/sub/imul/xor`、`xor eax,eax`=ゼロクリアのイディオム
   - `cmp`+`je/jne/jl/jg`(if文)、`jmp`(goto)
   - `call/ret`、`push/pop`
   - `[rbp-8]` などのメモリオペランド記法(スタック上のローカル変数アクセスの一例)
3. **関数呼び出しの完全理解(最重要)**
   - スタックは下方向に伸びる。callが戻り番地をpushする
   - スタックフレーム: 戻り番地/保存レジスタ/ローカル変数
   - **Windows x64呼出規約**: 引数はRCX,RDX,R8,R9(浮動小数はXMM0-3)、
     5個目以降はスタック、32バイトのshadow space、戻り値はRAX/XMM0
   - callee-saved / caller-saved レジスタ
   - これが第7章のABIの実体
4. **C構文とアセンブリの対応パターン**
   - if/while/for → cmp+jcc の形
   - 配列アクセス `a[i]` → `mov eax, [rcx+rdx*4]`
   - ポインタ間接参照 → メモリオペランド
   - 構造体メンバ → ベース+オフセット
   - 仮想関数呼び出し → vtableポインタのロード+間接call(第9章で再訪)
5. **ツール習熟**
   - **Compiler Explorer**: -O0と-O2の出力比較を日課にする
   - **VS逆アセンブリ**: ブレーク中に Ctrl+Alt+D。レジスタ/メモリ/
     コールスタックウィンドウとの併用
   - リリースビルドのデバッグ: 最適化でコード行と命令が一致しない現実
6. **最適化されたコードの読み方**
   - インライン展開で関数が消える、ループ回転、自動ベクトル化(SIMD命令の出現)
   - 「変数がレジスタに置かれ、メモリに存在しない」ことがある

## 重要概念

- **スタックフレーム** ── ローカル変数・再帰・コールスタックの正体
- **呼出規約(calling convention)** ── 関数間の暗黙の契約。ABIの核
- **Cの処理と命令列の対応を具体的に観察する** ── 一行対数命令という固定対応はない
- **最適化コードは原型を留めない** ── だから計測とツールが要る

## ゲーム開発との関係

| 現場の事象 | この章の知識 |
|---|---|
| リリース版のみのクラッシュをダンプ解析 | 逆アセンブリ+レジスタ読解 |
| スタックオーバーフロー/スタック破壊バグ | スタックフレーム |
| 「インライン化されてるか見て」 | Compiler Explorerで確認 |
| コールスタックウィンドウの仕組み | 戻り番地の連鎖 |
| クラッシュダンプの `RIP=0x0000...` | 命令ポインタ・関数ポインタ破壊 |
| チート対策・逆解析耐性の議論 | 機械語読解 |

## 演習

1. Compiler Explorer(x64 msvc/clang)で以下を -O0 / -O2 両方で読め:
   `int add(int,int)` / `int sum(int* a, int n)` / 再帰フィボナッチ /
   `struct Vec3{float x,y,z;};` を返す関数
2. VSでC++プログラムをデバッグ実行し、ブレーク→逆アセンブリ表示→
   F11で1命令ずつ実行しながらレジスタウィンドウでRAX等の変化を観察せよ。
3. 意図的なスタックバッファオーバーフローを書き、戻り番地が壊れて
   クラッシュする様子を逆アセンブリ+メモリウィンドウで観察せよ。
4. 関数呼び出し `f(1, 2.5f, ptr)` の直前でブレークし、RCX/XMM1/R8に
   引数が入る様子を確認せよ(Windows呼出規約の実物)。
5. アセンブリだけの小関数(2数の最大値)をMASMまたはインラインで書き、
   Cから呼び出せ(書くのはこれで最後。以後は読み専門でよい)。
6. Quake IIIの高速逆平方根を今こそ読み、各行を説明せよ(第1章の宿題回収)。

## この章がゲームのどこで使われているか

```
あなたが書くC++             命令列の説明例(Windows x64、最適化で変わる)
──────────────────────────────────────────────
player.pos.x += v * dt;  →  movss xmm0,[rbx+10h]
                            mulss xmm1,xmm2
                            addss xmm0,xmm1
                            movss [rbx+10h],xmm0
if (hp <= 0) Die();      →  cmp dword ptr[rbx+20h],0
                            jg   skip
                            call Die
Update(dt);              →  call命令 → スタックに戻り番地
                            → RCXにthis, XMM1にdt (呼出規約)
──────────────────────────────────────────────
クラッシュ解析・最適化確認・チート解析は全部この層で行う
コールスタック表示、ブレークポイント(int3命令)もこの層の技術
```
