# 第10章 データ構造・アルゴリズム・ゲーム数学 ── ゲームに効くものだけを深く

## 学ぶ理由

競技プログラミング全域は不要だが、**空間分割・ソート・ハッシュ・
グラフ探索**はゲームの毎フレームを支えている。そして3D数学(ベクトル・
行列・クォータニオン)は、Transform、カメラ、アニメーション、
レンダリング(第12章)の共通言語だ。ここを曖昧にしたままシェーダには進めない。

## 到達目標

- 計算量(O記法)を実測とキャッシュ効果込みで判断できる
  (「O(n)でも配列走査はO(log n)の木より速いことがある」を説明できる)
- ゲーム頻出データ構造を自力実装できる(動的配列・ハッシュ・プール・リングバッファ)
- ベクトル演算(内積・外積)の幾何的意味を即答できる
- 行列でモデル→ワールド→ビュー→射影の変換を組み立てられる
- クォータニオンで回転を扱え、オイラー角の問題点を説明できる
- A*でパス検索を実装できる

## 前提知識

第3章(キャッシュ)、第9章(C++)。高校数学(三角関数・ベクトル)。

## 学ぶ内容

### A. データ構造とアルゴリズム(ゲーム偏重セレクション)

1. **計算量とキャッシュの現実**
   - O記法の基礎。ただし定数項が支配する現実(第3章の回収)
   - 「小さいnなら配列線形探索が最速」問題
2. **ゲーム頻出のデータ構造**
   - 動的配列(vector)── 基本にして最強
   - **swap-and-pop削除**(順序を捨てて O(1) 削除)── ゲームの定番イディオム
   - ハッシュテーブル(オープンアドレス法がキャッシュに有利)
   - リングバッファ(入力履歴、ネットワーク、オーディオ)
   - 優先度キュー/ヒープ(A*、イベントスケジューラ)
   - 侵入型リンクリスト(エンジン内部で今も現役の理由)
   - ハンドル配列(generation付きID)── ダングリング対策の業界標準
3. **空間データ構造(ゲームの華)**
   - グリッド/ユニフォームグリッド(まずこれ。実は最強なことが多い)
   - クアッドツリー/オクツリー、BVH(レイキャスト・カリング・物理)
   - 空間ハッシュ
4. **アルゴリズム**
   - ソート: 基数ソート(描画キーソート)、std::sortの中身(introsort)
   - 探索: BFS/DFS、**A***(ヒューリスティック、ゲームAIの中核)
   - 補間: lerp、smoothstep、イージング関数(ゲームフィールの基礎)
   - 乱数: PCG/xorshift、シード再現性(リプレイ・デバッグ)

### B. ゲーム数学

5. **ベクトル**
   - 内積 = 射影・角度・「前にいる?」判定/外積 = 法線・左右判定・面積
   - 正規化、距離の2乗比較(sqrt回避)
6. **行列**
   - 4x4同次座標行列。平行移動・回転・スケールの合成
   - **行優先/列優先、行ベクトル/列ベクトル規約の地獄**(DirectXとOpenGLの差)
   - 逆行列・転置、法線変換に逆転置が要る理由
   - モデル→ワールド→ビュー→射影→NDC→スクリーンの変換連鎖
     (第12章レンダリングの数学的骨格。ここで完全に固める)
7. **回転の表現**
   - オイラー角(ジンバルロック・補間の破綻)
   - 軸角、**クォータニオン**(q v q⁻¹、slerp、なぜ4次元で3D回転か)
   - 回転行列との相互変換
8. **幾何と衝突の基礎(物理エンジンの入口)**
   - AABB/球/レイ/平面の交差判定
   - 分離軸定理(SAT)の概念
   - フラスタムカリングの数式(平面6枚と AABB)

## 重要概念

- **「アルゴリズムの理論次数」と「メモリの物理」の両輪**で判断する
- **swap-and-pop・ハンドルID・グリッド** ── ゲーム業界の三種の神器
- **内積と外積の幾何的直観** ── シェーダを読む前提
- **変換の連鎖(MVP行列)** ── レンダリングの背骨
- **クォータニオン** ── アニメーション・カメラの必需品

## ゲーム開発との関係

| 現場の事象 | この章の知識 |
|---|---|
| 「視界内の敵だけ処理」 | 内積・フラスタム・空間分割 |
| 数千体の衝突判定が間に合う | グリッド/BVHでO(n²)回避 |
| キャラの向き補間がおかしい | オイラー角→クォータニオンslerp |
| 描画順ソート(マテリアル・深度) | 基数ソート・ソートキー設計 |
| エフェクトの「気持ちよさ」 | イージング・補間 |
| NPCの経路探索 | A*・ナビメッシュ(発展) |
| リプレイが再現しない | 乱数シード・決定性 |

## 演習

1. generation付きハンドル配列(create/destroy/resolve)を実装し、
   解放済みハンドルへのアクセスが安全に検出されることを確認せよ。
2. 10万オブジェクトの近傍判定を(a)総当たり(b)ユニフォームグリッドで
   実装し、速度を比較せよ。
3. A*で2Dグリッド迷路のパス検索を実装し、ヒューリスティックの
   有無(=ダイクストラ)と比較せよ。
4. 4x4行列クラス(乗算・逆行列・透視射影)を自作し、
   「立方体をワイヤーフレームでスクリーン座標に投影して描く」
   プログラムを書け(GPUなし、CPUだけで。第12章の最高の準備)。
5. クォータニオンクラス(乗算・slerp・行列変換)を自作し、
   オイラー角のジンバルロックを実際に再現してから解決せよ。
6. 内積だけで「敵が自分の視野角120度以内にいるか」を判定する関数を書け。

## 理解度チェック

1. 内積が正/0/負のとき幾何的に何を意味するか。視野判定への応用は?
2. swap-and-pop削除の実装と、使ってよい条件(順序不問)を述べよ。
3. MVP変換の各行列は何から何座標系への変換か。
4. 法線の変換に逆転置行列が必要なのはなぜか。
5. ジンバルロックとは何か。クォータニオンはなぜそれを回避できるか。
6. O(n²)の衝突判定を空間分割がどう改善するか。グリッドの弱点は?
7. 「距離が10以下か」の判定でsqrtを避ける書き方は?
