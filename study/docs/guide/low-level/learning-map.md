## 0.1 最終目標の再確認

この教本のゴールはただひとつ。

> **「ゲームパッドのボタンを押してから、画面にゲームが表示されるまで」の
> 主要な仕組みと、さらに調べる必要がある部分を、自分の言葉で説明できるようになること。**

その流れを先にネタバレしておく。今は意味が分からなくてよい。
**各章を学びながら、この図の矢印を説明し、不明な箇所へ戻るために使います。**

```
[あなたの親指] ボタンを押す
   │ 物理接点が閉じ、電気が流れる
   ▼
[ゲームパッドのマイコン] ボタン状態をスキャンしUSB/BTパケット化   ←第1,2章
   │ USBポーリング(例:1000Hz)
   ▼
[OSのUSBドライバ/HIDスタック] 割り込み→カーネルが入力レポート受信 ←第8章
   │
   ▼
[入力API] XInput / GameInput / Windowsメッセージ                  ←第8,14章
   │ ゲームプロセスがポーリングで取得
   ▼
[ゲームループ] 入力→更新→描画 の毎フレーム反復                    ←第14章
   │ C++で書かれ、コンパイラが機械語へ変換したもの                 ←第5,6,7,9章
   │ CPUがキャッシュとレジスタを駆使して実行                       ←第2,3,4章
   ▼
[ゲームロジック/エンジン] シーン更新・物理・アニメ・ECS            ←第10,15,16,17章
   │
   ▼
[レンダラ] 描画コマンドを生成し グラフィックスAPIへ               ←第12,13章
   │ D3D12/Vulkan → GPUドライバ → コマンドバッファ
   ▼
[GPU] 頂点シェーダ→ラスタライズ→ピクセルシェーダ→フレームバッファ ←第11,12章
   │
   ▼
[ディスプレイ] Present/スワップチェーン→スキャンアウト→液晶が光る
   │
   ▼
[あなたの目] 「ジャンプした!」                        全経路 約30〜80ms
```

## 0.3 なぜこの順番か ── 依存関係グラフ

学習順の方針: **関連する基礎を先に扱い、後の章で具体例を見て戻れる順序にする**。

- **ハードウェア(1〜3章)が最初**な理由:
  C言語のポインタも、C++のパフォーマンスも、ECSの存在理由も、
  すべて「メモリとCPUがどう動くか」を知らないと**暗記**になってしまう。
  逆に知っていれば全部**当然の帰結**になる。
- **アセンブリ(4章)がCより前**な理由:
  Cの関数呼び出し・変数・ポインタを、具体的なCPUの命令列と対応させて学ぶ。
  ただしCは抽象機械の規則を持つ言語であり、構造化アセンブリそのものではない。
  最適化によって変数や処理が消える場合もある。
  (※Cを先に浅く触り、アセンブリ後にCを深掘りする螺旋でもよい)
- **C(5,6章)がC++(9章)より前**な理由:
  Cの構造体・関数ポインタ・動的確保は、C++の実装を読む足場になる。
  ただしC++はCと異なる型・オブジェクト寿命・所有権の規則を持つ。
  `class`・`virtual`・`std::vector`は、Cの機能を包んだだけのものとして扱わない。
- **コンパイラ/リンカ(7章)がOS(8章)の前**な理由:
  「実行ファイル(EXE)とは何か」を知って初めて「OSがそれをロードして
  プロセスにする」が理解できる。
- **OS(8章)がGPU(11章)より前**な理由:
  GPUとの通信はすべてドライバ=OSの仕組み(DMA、割り込み、メモリマップ)の上にある。
- **GPU(11〜13章)がエンジン(15章〜)より前**な理由:
  エンジンのレンダラ設計(バッチング、カリング、レンダーグラフ)は
  GPUとAPIの制約から逆算されたもの。制約を先に知る。
- **Unity/UE(16,17章)が自作エンジン概念(15章)より後**な理由:
  一般論(エンジンとは何か)を持ってから個別実装を見ると、
  「UEはここをこう解いたのか」と差分で読める。丸暗記にならない。

## 0.4 学習の三本柱

すべての章で、この3つを回す。

1. **読む** ── 教科書・ドキュメントで概念を得る
2. **書く** ── 小さなコードで検証する(各章の「演習」)
3. **覗く** ── デバッガ・逆アセンブリ・RenderDoc・OSSソースで実物を確認する

「覗く」が最重要。**この教本の差別化は「実物を覗く訓練」にある。**
理解とは「教科書の記述と、画面に映る実物が一致した瞬間」に起きる。

## 0.5 環境構築(最初にやる)

Windows 11想定。以下を入れておく(全章で使う):

- **Visual Studio 2022 Community**(C++デスクトップ開発ワークロード)
  - 逆アセンブリ表示・メモリウィンドウ・診断ツールまで使い倒す
- **Git** と GitHubアカウント(OSSソースを読むため)
- **RenderDoc**(グラフィックスデバッガ、第12章以降)
- **PIX on Windows**(D3D12プロファイラ、第13,18章)
- **WSL2 + Ubuntu**(Linux側の実験用: ELF、straceなど第7,8章)
- **Compiler Explorer (godbolt.org)** をブックマーク(第4章から毎日使う)
- **CMake**(OSSをビルドするため)
- 余裕があれば: **Tracy Profiler**、**Superluminal**(体験版)

## 0.6 学習記録のすすめ

- このフォルダに `notes/` を作り、章ごとに「自分の言葉での要約」と
  「実験結果(逆アセンブリのスクショ等)」を残す。
- **人に説明できないものは理解していない。** 各章の理解度チェックは
  「口頭で説明する」つもりで答えること。
