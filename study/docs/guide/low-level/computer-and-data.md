# 第1章 コンピュータとは何か ── 情報の表現

## 学ぶ理由

すべてのゲームデータ ── 座標、HP、テクスチャ、サウンド、セーブデータ ── は
最終的に**ビット列**である。「floatの精度でキャラがガタつく」「色が変」
「セーブデータが壊れた」といった実務のバグは、ビットレベルの表現を
知らないと原因にたどり着けない。ここは全20章の土台の土台。

## 到達目標

- 任意の整数を2進数・16進数で読み書きできる
- 2の補数表現を説明でき、`(int)-1 == (unsigned)0xFFFFFFFF` の理由が分かる
- IEEE 754浮動小数点の構造(符号・指数・仮数)を説明できる
- 「floatで0.1が正確に表せない」「大きな座標で精度が落ちる」理由が分かる
- 文字コード(ASCII/UTF-8)とエンディアンを説明できる

## 前提知識

なし。ここが出発点。

## 学ぶ内容

1. **2進数・16進数**
   - ビット、バイト、ワード。なぜ16進数を使うか(4bit=1桁でビットと相性が良い)
   - ビット演算: AND/OR/XOR/NOT、シフト。フラグ管理 `flags |= JUMPING`
2. **整数の表現**
   - 符号なし整数、2の補数(なぜ「補数」だと加算器1つで減算もできるのか)
   - オーバーフロー: C/C++の符号なし整数は型の範囲で剰余計算される。
     符号付き整数の表現範囲を超える算術は未定義動作であり、常に巻き戻るとは限らない
   - 固定小数点数(昔のゲーム機や、演算の再現性を設計したい場面で使う)。
     これを選ぶだけで決定性が保証されるわけではなく、丸め・溢れ・処理順も揃える
3. **浮動小数点 (IEEE 754)**
   - 本章では一般的なIEEE 754 binary32のfloatを例にする:
     符号1 + 指数8 + 格納する仮数部23bit。C/C++の型名だけでこの形式が保証されるわけではない
   - 精度の偏り: 0付近は細かく、大きくなるほど粗い
     → **オープンワールドで原点から離れるとアニメがガタつく理由**
     (対策: カメラ相対レンダリング、ワールドオリジンシフト)
   - 特殊値: NaN, Inf, -0。NaNは伝染する(`NaN != NaN` に注意)
   - binary64の例では `0.1 + 0.2 != 0.3` となる。比較方法は用途で選ぶ。
     近似一致は値の規模に応じた相対許容誤差と、0付近の絶対許容誤差を検討する。
     型のepsilonを全ての値へ固定で当てはめない。厳密一致が必要な場合やNaN/Infも別途扱う
4. **文字と色の表現**
   - ASCII、Unicode、UTF-8/UTF-16(WindowsとUEはUTF-16、多くのファイルはUTF-8)
   - 色: RGBA8888、リニア色空間とsRGB(第12章で再訪)
5. **エンディアン**
   - リトル/ビッグエンディアン。x86もARMもGPUも基本リトル
   - バイナリファイル(アセット)やネットワークで問題になる
6. **ノイマン型アーキテクチャの概観**
   - 「プログラムもデータもメモリに置かれ、CPUが命令を1つずつ実行する」
   - この1行が以後の全章の前提

## 重要概念

- **ビットは意味を持たない。解釈が意味を与える。** 同じ32bitが
  int にも float にも 色にも 命令にもなる。キャスト・シリアライズ・
  型パンニングの理解はここから。
- **2の補数**: 加算回路だけで減算が実現できる天才的表現
- **浮動小数点には表現と演算の丸めがある**: 許容できる誤差と、その扱いを設計する
- **精度は相対的**: floatは「約7桁の10進有効数字」

## ゲーム開発との関係

| 現場の事象 | この章の知識 |
|---|---|
| ビットフラグでの状態管理 | ビット演算 |
| 座標が大きいと物理・アニメが暴れる | floatの相対精度 |
| リプレイ再現が環境でズレる | 演算順・コンパイラ設定・乱数・更新順の再現性。固定小数点も選択肢 |
| セーブデータ/アセットのバイナリ解析 | 16進ダンプ、エンディアン |
| 日本語ファイル名/テキストの文字化け | UTF-8/UTF-16 |
| HDR対応で色が変わった | 色の数値表現・色空間 |

## 演習

1. 電卓を使わず 0xDEADBEEF を10進・2進に変換せよ。
2. C++で `float f = 16777216.0f; f += 1.0f;` を実行し、値が増えないことを
   確認せよ。なぜ16777216(2^24)なのか、仮数23bitから説明せよ。
3. `float`のビットを`memcpy`で`uint32_t`に写し、符号・指数・仮数を
   自力で分解して表示するプログラムを書け(1.0f, -2.5f, 0.1fで確認)。
4. プレイヤー状態(ジャンプ中/無敵/ダッシュ中...)を1つの`uint32_t`の
   ビットフラグで管理する関数群(set/clear/test)を書け。
5. バイナリエディタ(VSの「バイナリで開く」やHxD)でBMPファイルを開き、
   ヘッダの幅・高さをリトルエンディアンで読み取れ。

## この章がゲームのどこで使われているか

```
ボタン → OS → ゲームループ → エンジン → GPU → 画面
                  │            │        │
                  ▼            ▼        ▼
           HP,座標,フラグ   Transform  頂点データ,色
           = int/float     = float×16  = float/半精度/sRGB
           ─────────── すべて「ビット列+解釈」───────────
     セーブデータ・アセットファイル・ネットパケットも全部バイト列
```
