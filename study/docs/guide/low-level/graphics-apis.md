# 第13章 グラフィックスAPI

## このページで案内すること

描画APIの共通概念を押さえ、資源管理・コマンド・同期を一つのAPIで試すための**学習計画・概要**です。全APIを同時に習得することを求めるものではありません。比較してから、使う環境に合う実験対象を選びます。

## 関連する辞典本文・実践

- [API横断比較](/graphics/api/comparison.html)で、共通点と責任範囲の違いを整理できます。
- [OpenGL](/graphics/api/opengl.html)、[Direct3D 12](/graphics/api/directx12.html)、[Vulkan](/graphics/api/vulkan.html)で、個別の仕組みを調べられます。

## 学ぶ理由

エンジンのレンダラはグラフィックスAPIの上に建つ。UE5のRHI、UnityのSRPは
D3D12/Vulkan/Metalの抽象化層だ。モダンAPI(D3D12/Vulkan)は
「ドライバがやっていた仕事(メモリ管理・同期・状態管理)をアプリに開放」
したため、**APIを学ぶこと自体がGPUとドライバの仕組みを学ぶこと**になる。
RenderDoc/PIXでフレームを読むにも、API概念(コマンドリスト、バリア、
ディスクリプタ)の語彙が必須である。

## 到達目標

- 旧世代(OpenGL/D3D11)とモダン(D3D12/Vulkan)の設計思想の違いを説明できる
- スワップチェーン・コマンドリスト・フェンスによるCPU-GPU同期を実装できる
- リソースバリア(状態遷移)とディスクリプタの概念を説明できる
- D3D12またはVulkanで「テクスチャ付き立方体」まで自力実装できる
- PSO(パイプラインステートオブジェクト)とシェーダコンパイルの関係を説明できる
- 「ドローコールが重い」の正確な意味を説明できる

## 前提知識

第8章(OS・ドライバ)、第11章(GPU)、第12章(パイプライン)。C++(第9章)。

## 学ぶ内容

1. **APIの系譜と設計思想**
   - OpenGL/D3D11(ドライバが賢い、ステートマシン、シングルスレッド前提)
   - D3D12/Vulkan/Metal(アプリが賢い、明示的、マルチスレッド前提)
   - なぜ移行したか: ドローコールのCPUコスト・ドライバの推測の限界・
     マルチコア活用(AZDO→Mantle→の歴史)
   - どれを学ぶか: **概念習得はOpenGLかD3D11で速く、本命はD3D12
     (Windows/Xbox)を1つ深く。Vulkanは差分で理解**(概念は9割共通)
2. **初期化とスワップチェーン**
   - デバイス/アダプタ列挙、デバッグレイヤー(必ず有効化する習慣)
   - スワップチェーン: バックバッファ、ダブル/トリプルバッファリング
   - Present、VSync、可変リフレッシュ(入力遅延との関係 ← 第14章へ)
3. **コマンド実行モデル(モダンAPIの心臓)**
   - コマンドアロケータ→コマンドリストに記録→キューへ提出
   - GPUは後から非同期に消費(第11章の回収)
   - **フェンス**によるCPU-GPU同期、フレームインフライト(2〜3フレーム並走)
     → 「入力から表示まで数フレームかかる」理由の核心
   - 複数キュー(グラフィックス/コンピュート/コピー)と非同期コンピュート
4. **リソースとメモリ**
   - バッファ/テクスチャ、ヒープ(DEFAULT=VRAM, UPLOAD=CPU可視)
   - アップロードの作法(ステージングバッファ→コピー)
   - **リソースバリア/レイアウト遷移**: 「テクスチャとして読む前に
     レンダーターゲット書き込み完了を保証」── GPUキャッシュと
     圧縮形式の切替をアプリが指示する(第11章の帯域最適化の裏側)
   - ディスクリプタ(リソースのGPU向けポインタ)、ディスクリプタヒープ、
     ベースのバインドレス化の潮流
5. **パイプラインステートオブジェクト(PSO)**
   - シェーダ+ブレンド+深度+ラスタ設定を1オブジェクトに焼き固める
   - **シェーダコンパイルスタッター**(実行中PSO生成のヒッチ)と
     PSOキャッシュ ── 現代PCゲームの有名問題の正体
   - ルートシグネチャ(D3D12)/パイプラインレイアウト(Vulkan)
6. **描画の1フレーム(統合)**
   - リソース更新(定数バッファ)→バリア→パス毎にRT設定→
     PSO設定→ディスクリプタ→DrawIndexedInstanced→…→Present→フェンス
   - **ドローコールのコスト分解**: API呼び出し+ドライバの検証+
     ステート切替。インスタンシング・バッチングが効く理由
7. **デバッグとツール(第18章へ接続)**
   - デバッグレイヤーのメッセージを読む、GPUバリデーション
   - RenderDoc(API横断)と PIX(D3D12特化)の使い分け

## 重要概念

- **明示性**: モダンAPIは「ドライバの魔法」を全部アプリに渡した
- **コマンドバッファ+フェンス** ── CPUとGPUの生産者消費者関係
- **フレームインフライト** ── スループットと遅延のトレードオフ
- **バリア** ── GPU内部の並列性とキャッシュを制御する行為
- **PSO** ── 実行中のシェーダコンパイルを排除する設計

## ゲーム開発との関係

| 現場の事象 | この章の知識 |
|---|---|
| UEのRHI / UnityのSRP・Graphics API設定 | この章の抽象化層 |
| シェーダコンパイルスタッター問題 | PSO・ドライバコンパイル |
| 「ドローコール削減」「バッチング」 | コマンドのCPUコスト |
| GPUクラッシュ(デバイスロスト)解析 | バリア・同期ミス・TDR |
| 入力遅延とトリプルバッファリング | スワップチェーン・インフライト |
| ロード画面でのテクスチャ転送設計 | アップロードヒープ・コピーキュー |

## 演習

1. **Win32ウィンドウ+D3D12初期化**を(チュートリアルを見ながらでよいので)
   自分の手で全行書き、画面クリアまで到達せよ。デバッグレイヤー必須。
   (Vulkan派は vulkan-tutorial.com で同等の三角形まで)
2. 三角形→テクスチャ付き立方体→定数バッファでMVP更新、まで拡張せよ
   (第12章の演習をモダンAPIで再構築する)。
3. フェンスを意図的に省略/誤らせて、何が壊れるか観察せよ
   (デバッグレイヤーの警告を読む訓練)。
4. 同じモデル1000体を (a)個別ドローコール (b)インスタンシング で描き、
   CPU時間を比較せよ(PIXで計測)。
5. RenderDocで市販ゲーム級の複雑なフレーム(自作でなくてよい、
   例: 任意のOSSゲームやUE5サンプル)をキャプチャし、パス構成
   (シャドウ→Gバッファ→ライティング→ポスト→UI)を読解してノートに図解せよ。
6. トリプルバッファリングとVSyncオフで入力遅延の体感差を確認せよ。

## 理解度チェック

1. D3D11とD3D12の最大の違いを「誰が何を管理するか」で説明せよ。
2. コマンドリスト・キュー・フェンスの関係を生産者消費者で説明せよ。
3. フレームインフライトが2〜3ある理由と、入力遅延への影響は?
4. リソースバリアは何を保証するものか。なぜ手動なのか。
5. PSOはなぜ「事前に」作るのか。実行中に作ると何が起きるか。
6. ドローコールのコストはCPU側とGPU側のどちらに主にかかるか。その内訳は?
7. スワップチェーンのPresentから画面点灯までに何が起きるか(概要)。
